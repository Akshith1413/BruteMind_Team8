# AI Engine & Multi-Agent Architecture Documentation - Aetheris OS

This document details the AI architecture, agent specifications, semantic boardroom consensus protocols, and synthetic customer simulators for Aetheris OS.

---

## 🤖 The 10-Agent Swarm Specifications
Aetheris OS utilizes ten distinct agents. Each has a specialized system prompt, input constraint, and output payload format:

| Agent Name | Primary Responsibility | Input Source | Output Format |
|---|---|---|---|
| **CEO Agent** | Swarm moderator, resolve boardroom deadlocks, final strategy sign-off. | User query + Agent votes. | Unified Growth Protocol JSON. |
| **CFO Agent** | Burn-rate controller, unit economics compliance, budget approvals. | CMO spend requests + Financials. | Budget limits & Risk Warnings. |
| **CMO Agent** | Target audience modeling, copywriting generation, ad placements. | Business Profile + Competitor data. | Campaign templates & copy drafts. |
| **CSO Agent** | Funnel conversion, outreach triggers, pipeline layout optimizations. | Lead metrics + CRM stages. | Active email sequences & funnel steps. |
| **COO Agent** | Bottleneck detection, execution speed audits, workforce syncs. | Telemetry logs + Active tasks. | Bottleneck Alerts & job profile specs. |
| **R&D Agent** | Competitor updates, feature backlog proposals, patent scans. | Market logs + Scraping indices. | Feature roadmaps. |
| **CS Agent** | Churn analysis, CSAT scores, support volume indexing. | Customer feedback + Support logs. | Churn warnings & retention campaigns. |
| **Legal Agent** | GDPR, HIPAA, and marketing compliance audits. | Drafted campaigns & scripts. | Compliance Signature or Veto text. |
| **HR Agent** | Workload balancing, talent recruitment planning. | COO bottleneck alerts. | Hiring proposals & team splits. |
| **Data Analyst** | Document segmentation, Vector DB storage, RAG retrieval. | PDFs + Telemetry streams. | Cleaned metrics & semantic vector clouds. |

## 🗳️ Semantic Consensus Voting Loop
Decisions are not generated by a single prompt. Instead, they require a simulated boardroom vote:
1. **Proposal Phase**: The CEO agent states the growth goal (e.g. "Increase Q3 sales by 15%").
2. **Specialty Phase**:
   - The **CMO** proposes a budget and ad platforms.
   - The **CSO** proposes a targeted cold-outreach schedule.
3. **Audit Phase**:
   - The **CFO** evaluates the cost-per-acquisition (CPA) projections. If CPA is too high, the CFO votes `REJECT` and writes a feedback payload.
   - The **Legal Agent** scans the copy templates for false claims or privacy risks. If flagged, votes `REJECT`.
4. **Resolution Phase**:
   - If votes are unanimous, the **CEO** signs off.
   - If vetoed, the **CEO** summarizes the failures and triggers a second iteration loop, ordering the CMO/CSO to reformulate.

## 📂 RAG Context Ingestion Flow
```
User Uploads PDF ──> Data Analyst Segmenter ──> Text Embedding (Gemini) 
                                                      │
                                                      ▼
CEO Query <── RAG Retrieve Context <── Query Matching (Vector DB)
```
1. **Ingestion**: Documents are chunked into 500-character segments with 50-character overlaps.
2. **Vectorization**: Embedded using Gemini's `text-embedding-004` model.
3. **Retrieval**: During boardroom debates, agents query the database using semantic search, attaching relevant segments to their LLM context window.

## 👥 Synthetic Buyer Simulator Sandbox
To verify strategy impact, the backend simulates 30 **Synthetic Buyer Personas**:
* Each persona is represented as an object:
  ```json
  {
    "id": "buyer_04",
    "persona": "SaaS Operations Director",
    "budgetCeiling": 5000,
    "painPoints": ["inefficient pipelines", "lack of integration"],
    "channelPreference": ["LinkedIn", "Direct Email"],
    "attentionSpan": 0.45
  }
  ```
* Deployed marketing campaigns flow to the simulator. 
* The backend runs a probability matrix check: if the campaign's messaging matches the buyer's pain points and is deployed on their channel preference, the buyer converts.
* The simulator logs these decisions in real-time, feeding live conversion charts on the frontend dashboard.
